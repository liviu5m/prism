The steps, in order:
1. Dev gate (now). Score base and SFT on dev. If SFT > base, Phase 2 closes. If not, diagnose before anything else.
2. Checkpoint choice. Score checkpoint-63 and checkpoint-84 on dev. Keep the winner. Write run_manifest.json. Still no training.
3. Eval harness (Phase 3). Same harness, now pointed at test_in and test_out, base and SFT in one table, plus confidence intervals, per-pattern slices, and an error taxonomy. Output: reports/eval_v1.md + JSON. Still no training. This report is your headline result.
4. Read the taxonomy, then decide. This is the only route to more training. If errors cluster — say most failures are missing WHERE clauses or wrong joins — you add training examples for those patterns, rebuild the dataset as v2 (never edit v1), and retrain SFT. Measure again on dev, then once on test.
5. DPO — optional, one more training stage. Not "train more on the same data". It needs preference pairs: for each train prompt, sample 4 answers from your SFT model, score each by running it (execution accuracy is your reward), keep pairs where best > worst, label chosen/rejected. Then train DPO on those pairs. Gate: reward margins must be non-zero (the old run had rewards/margins = 0.0 and a bit-identical adapter — a proven no-op). If test accuracy doesn't improve with a CI on top, report the null result and stop.
6. Merge + quantize. No training. Merge adapter into fp16 → merged_fp16. Quantize to W4A16 with calibration prompts from your own train set → merged_w4a16. Measure disk size, VRAM, latency, and re-run the task harness. Output: reports/quant_report.md, including the accuracy you lost for the memory you saved.
7. Serve. vLLM + FastAPI + a queue that never silently drops requests (429 + Retry-After). Parity check: same 20 prompts through local HF and through the endpoint must match — this catches prompt-template drift. Load test gives throughput/latency numbers.
8. A/B + dashboard. Two variants behind sticky routing, per-variant metrics, cost/latency chart, and a written promotion or rollback decision. Autoscaling is simulated on one GPU — label it.
9. Final report + CI. One README table: base vs SFT vs DPO vs w4a16, on test_in and test_out, with CIs. That table is the project.
